# RGB + Utility lab annex components

`labs-15.txt` and `labs-30.txt` are Factorio blueprint strings generated by
`makeLabAnnex` in `scripts/rgby-science/labs.mjs`. `manifest.json` lists both;
`labs-15.manifest.json` and `labs-30.manifest.json` carry individual metadata.
All positions and entity numbers are local. Remap entity IDs, wire endpoints,
port IDs, and `flight_science_entity` tags when composing another blueprint.

Footprints: 15 labs use 45×6 tiles; 30 labs use 45×10 tiles. Both have two
parallel eastbound red belts and west input ports. Belt 1: red north lane,
green south lane. Belt 2: blue north lane, yellow south lane. Medium poles form
a connected copper grid; each lab accesses both belts with fast and
long-handed inserters. No modules or requester chests.

Sizing formula: `floor(SPM * researchSeconds / (60 * researchSpeed))` for
normal labs and research using one of each pack per unit. At 30/min per pack
and speed 1 this supports 15 fully-fed labs for 30-second research or 30 for
60-second research. Speed upgrades reduce the fully-fed count. The manifest's
15-lab sizing assumption is 30 seconds; **both native runs used 60 seconds**.

## Preserved evidence

`native-report.json` is the exact, byte-for-byte successful original report
from run `native-1794797933267`, game **2.1.24**. Build index 0 is rows=1,
15 labs; build index 1 is rows=2, 30 labs. All 45 labs saw all four packs,
had power, and performed research. Both variants passed. Test duration was
21,600 ticks (six simulated minutes), with saturated west belt lanes supplied
every eight ticks and lab inventories/status sampled every 60 ticks.

This proves standalone annex supply and research under saturated input.
**It does not prove 30/min factory production capacity, factory-to-lab
connections, or sustained paired factory throughput.** No native 2.0.77 run
is claimed. Blueprint headers target 2.0.77; strings are round-trip decoded,
but the original native test directly created entities rather than importing
these exported strings.

`native-spec.json` preserves both exact input builds and test conditions.
`native-control.lua` and `native-data.lua` preserve the actual tested harness
source. `source-proof.json` binds these files, the unchanged generator and
original test source, and the exact original report by SHA-256. The original
report's `entityWireSha256` binds each tested entity/wire set, which the exporter
checks against the generated blueprints. Blueprint string hashes exclude the
trailing newline; source/report hashes include all file bytes. The raw dump
hash identifies the supplied prototype input, not the running 2.1.24 prototype
set. No dumps, saves, mods, or logs are packaged here.

## Export and verify

Run from the project root:

```sh
node blueprint-sources/rgby-science/components/labs/export.mjs /path/to/data-raw-dump.json
node blueprint-sources/rgby-science/components/labs/native-run.mjs
```

The export module also provides `exportLabAnnexes(raw, {prototypeSha256})` and
`verifyEvidence()`. It fails if the generator, preserved sources, or tested
entity/wire sets have drifted. Export only writes this component directory.

To rerun the preserved native harness with the recorded installed version:

```sh
FACTORIO_APP='/path/to/factorio.app' node blueprint-sources/rgby-science/components/labs/native-run.mjs --run
```

Runtime fixtures, profile, saves, logs, and fresh reports stay exclusively in
`.cache/rgby-labs/preserved-<timestamp>`; preserved evidence is never overwritten
by a native rerun. The runner verifies preserved hashes before launching and
uses the frozen spec rather than rebuilding from changed source.
