# twenty-robot-caps (qualified, superseded by the full-stack caps)

The 21 November string with the output chest stopping each product at 20 construction robots, 20 logistic robots, 2 roboports, 10 storage chests and 10 passive provider chests. Same footprint (33 x 16 = 528 tiles), machines, entrances, ring limits, reserves, two-speed clock and supply gate as the current string; the only difference is the five filter decider constants next to the output chest (and the blueprint description that names them).

- Evidence: `native-report.json` (saturated entrances) and `panel-supply-report.json` (every entrance at exactly its panel figure) are the full-protocol reports for this exact string (SHA-256 `afdc129e...4c48`, `passed: true`): steady 5.53 / 5.5 / 0.6 / 2.2 / 2.2 saturated and 4.9 / 4.9 / 0.5 / 2.0 / 2.0 at the panels, exact blocked caps 20 / 20 / 2 / 10 / 10, all five selective phases. They were run with an 8 minute closed hold and 5 minute selective settles, and with the harness and validator as they were then; the current `control.lua` and `validate.mjs` only add the cap-reached timing, so the report hashes inside these files do not match the scripts as they are now.
- Why superseded: twenty robots in the chest is too little to take a few at a time. The current string stops each product at one full stack (50 / 50 / 10 / 50 / 50). Both versions stay selectable (`versions` in the family manifest).
- Reproduce: the string is kept as a file; the current generator builds the six-product string only. The generator as of the commit before the requester chest change (`git log -- scripts/robot-essentials/generate.mjs`) rebuilds it with `RE_OPTIONS` (caps overrides).

- Later: the full-stack five-product string was itself superseded by the requester chest string; see `../five-products-full-stack/NOTE.md`.
